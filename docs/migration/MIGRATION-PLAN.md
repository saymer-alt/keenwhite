# План миграции WL/WDTT в KeenWhite — исторический план и текущие гейты

**Актуализация 22.10.2026:** этапы KW-M0 (репозиторий/защита) и KW-M1 (GPL-3.0 WDTT subtree с полной историей, [PR #1](https://github.com/saymer-alt/keenwhite/pull/1)) завершены. Вложенный Go/race/ARM64/MIPSel QEMU CI прошёл. Перечисленные ниже императивные шаги M0/M1 сохранены как **история процедуры**, повторно выполнять их нельзя. Следующий этап — адаптер, операторская безопасность и физическая приёмка; **нет продукта stable, autostart, устройства/установщика**.

## Принятое решение

`keenwhite` — новый самостоятельный GitHub-репозиторий (НЕ fork). Он становится **единой площадкой собственных разработок для ограниченных сетей Keenetic/Netcraze**: архитектура, клиенты/адаптеры, ядро CLI, manifest/API, сценарии тестирования, артефакты CI, приёмка, roadmap и сопровождение. Это **не обещание**, что все upstream transport executables сразу будут встроены в один бинарник.

- **KAS**: установщик/обновление/удаление как отдельного опционального компонента, интеграция с существующим supervisor, без переноса сетевого runtime в setup.sh.
- **KeenWhite**: собственный runtime manager (пока только offline CLI), первый поддерживаемый модуль WDTT, потенциальные OpenFlux и новые транспорты/адаптеры. Все новые инженерные Issues для white-list transport поднимать здесь.
- **Исходные форки**: upstream tracking и временный provenance-архив, без нового продуктового функционала после перехода (кроме исправлений до cutover). Не удалять до успешной миграции и сохранения PR/release links.

## План в этапах

### KW-M0 — создание репозитория (немедленно)
1. В GitHub аккаунте `saymer-alt` создать публичный **новый** repo `keenwhite` (нет template/fork). Описание: `Independent multi-transport toolkit for Keenetic/Netcraze: original management CLI, WDTT source migration, pluggable carriers, offline-first diagnostics and safe KAS integration.`
2. Загрузить собственный KeenWhite каркас как новый root commit, включить Actions, активный ruleset default `main` (запрет deletion/force-push, PR-only, 0 обязательных approvals, без bypass, не требовать несуществующих CI checks).
3. Проверить Go tests+race+vet, ARM64/MIPSel **build-only** без публикации бинарников.
4. Никаких release/tag/автоустановки.

### KW-M1 — перенос репозитория WDTT с историей
1. Пиннуть commit PR #42 `d39f9dad91639a0f1ca321df72f3dc51ff0b0af0`. Проверить upstream remote, copyright, лицензию GPL-3.0, provenance всех зависимостей, безопасность приватных образцов в истории импорта.
2. Создать `migration/wdtt-pr42-<sha>` от нового `main` и импортировать **без squash** Git-subtree всего исходного WDTT внутрь `transports/wdtt/` с помощью `scripts/import-wdtt-history.sh --apply` (команда по умолчанию только печатает план). Импорт полного репозитория сохраняет Android/server legacy код в поддереве на первом этапе, но **не включает его в стандартный Go build KeenWhite**.
3. После импорта проверять git-историю (`git log`), SPDX, наличие GPL LICENSE, отсутствие приватных данных в новых коммитах и собственные/транспортные независимые go.mod и test suites. **Draft PR**, без merge до acceptance.
4. На следующем шаге решить, какую часть `go_client`, `server.go`, `app` оставлять в активной поддержке KeenWhite: цель — Keenetic/Entware. Удаление невостребованного legacy-кода отдельным PR с сохраняемой историей.
5. Транспортный код WDTT — GPL-производный. Новые собственные модули/адаптеры KeenWhite — MIT, в отдельном Go module/process. Нельзя механически объединять эти лицензии в одном бинарнике без отдельного заключения.

### KW-M2 — реестр накопленных работ и перенос задач
1. Краткий индекс прежних экспериментов WDTT (27 веток), действующих Draft PR и release pin в `WDTT-SOURCE-LEDGER.md`. Исходные PR остаются доступными и открытыми до принятого решения.
2. Перенести **приоритетные решения и acceptance**, а не слепо копировать сотни GitHub Issues: один umbrella issue KeenWhite и небольшие задачи `WDTT correct lifecycle`, `Security/redaction`, `18/1+UDP field acceptance`, `Memory and resource budget`, `BusyBox/Entware package provenance`.
3. Добавить links back на старые issue и PR; не создавать одновременно конкурирующие источники истины после cutover.
4. Исследования MT-001/MT-002/MT-007 из KAS пересобрать в `docs/research/` в KeenWhite после проверки конфликтов и версии контракта; в старом KAS оставить ссылки/архив, не закрывать незаконченные PR как будто они выпущены.

### KW-M3 — самостоятельно поддерживаемые провайдеры
1. WDTT в дереве, его валидированный Keenetic/Entware клиент собирается из KeenWhite в собственной изолированной CI, но **не объявляется stable**.
2. OpenFlux — второй независимый кандидат: создать собственный адаптер процесса/manifest, тесты, документацию независимых carriers; если возникнет необходимость в форке/переносе GPL исходников, отдельное решение. Нельзя выдавать Mail.ru за независимую от VK компанию; `direct` проверить отдельно от стороннего транспорта.
3. CSQTT/Swinter/whitelist-bypass/WhiteTransport — источники идей и тестовых сценариев. Писать свой код, соблюдать лицензии; экспериментальные бинарники нельзя молча включать в install-all.
4. Диагностика `LISTEN ≠ E2E`; fail-closed, секреты `0600/0700`, zero WAN/DNS bypass, нет второго supervisor KAS.

### KW-M4 — KAS интеграция после физической приёмки
- KAS поддерживает независимую pinned установку **KeenWhite** и не содержит свой второй, дублирующийся transport manager.
- Устройство ARM64 NC-4210 сначала проходит контролируемый owner-lab; KN-1012 512MB отдельно, MIPSel отдельно. KAS+WDTT ≥512MB остаётся своим gate, не распространяется на core KAS и OpenFlux без измерения.
- Rollback/uninstall не удаляет чужие файлы, публичные сети/маршруты не меняются по умолчанию.

## Что НЕ значит «всё в одном репозитории»

- Не переносить приватные ключи/профили/токены и реальные сетевые логи.
- Не копировать в KeenWhite все 27 веток как активные feature-потоки.
- Не переписывать историю Git, уничтожая авторство upstream.
- Не делать форк KeenWhite от WDTT/OpenFlux: собственный root commit и поддеревья с прозрачной атрибуцией.
- Не считать коммерческую, правовую или техническую пригодность перенесённого исходника автоматически проверенной.
- Не сливать текущие Draft PR WDTT/KAS по умолчанию, не прекращать поддерживаемые prerelease URLs до замены.
